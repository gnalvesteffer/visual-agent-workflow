# 0002: separate execution scheduling from typed data

**Status:** Accepted as the prerequisite design for the deterministic visual-programming milestone.

**Context:** The current schema serializes graph connections as `Kind = "data"`, while the runner also uses those same connections to schedule the next node and pass one message value. This is adequate for the existing bounded message-flow graph, but it cannot express Blueprint-style pure values: a constant or arithmetic node must provide data without causing downstream work to execute. Adding such nodes before separating these meanings would create misleading authoring behavior and make a data wire an implicit control-flow edge.

**Decision:** New graph semantics will represent execution and data as distinct typed channels with stable node/port identities. An execution edge activates a target according to the scheduler contract. A data edge only binds a typed value to a target input; it never activates a node. Ports declare their direction, kind, data type/schema, cardinality, optional/default behavior, and stable label/ID independently of canvas position or display text. The compiler and validator check both channels and prepare an executable plan before a run starts.

Pure expression nodes are deterministic, bounded, and side-effect free. Their values are evaluated in the consumer activation's context; graph position does not define evaluation order, and purity does not imply global caching. Effectful nodes such as model, MCP, approval, wait, and child-workflow operations require explicit execution activation. A successful effect result is retained for that activation so multiple data consumers do not repeat the external call. Mutable values remain out of scope until state lifetime, loop visibility, and parallel branch isolation/merge behavior are specified.

**Compatibility:** Existing schema versions keep their current interpretation and canonical serialization. Their legacy `data` connection is compiled through a compatibility plan that preserves both its current activation and message-transfer behavior. New schema versions use explicit execution and data declarations. Import, restore, and package loading never silently rewrite a published definition; any explicit upgrade produces a reviewable draft and preserves the original revision/hash.

**Evidence and activation identity:** A data value is available only in the execution context that produced or supplied it. Runtime evidence must identify the run, nested call path, node, activation, and loop iteration/attempt where relevant. A loop iteration cannot consume stale values from a previous iteration. A join may combine only branch results belonging to the same fork activation. Replay reads recorded values and routes and never evaluates a live model/tool or reruns an effect.

**Consequences:** Constants and pure operators depend on the new edge/scheduler contract, not merely a node card and a type picker. Contextual pin search can use the same port descriptors as validation, but it remains an authoring aid. This first increment will prove a mixed graph with one explicit entry, one constant, one deterministic operator, a branch, and output; broader collections, mutable variables, reusable functions, and async nodes follow only after their contracts are independently bounded and tested.

**Source:** Adapted from the project's [Unreal Blueprint capability reference](../unreal-blueprint-reference.md), especially its nodes/pins/wires, pure evaluation, activation identity, node-definition contract, and compiler/validator/runtime-scheduler subsystem guidance. The workflow-specific decisions above are not claims about Unreal runtime compatibility.
