# Studio editor design system

The Studio is a focused workflow editor for building and inspecting agent graphs. The graph remains the primary workspace, and the shell can match the operator's preferred editor theme.

## Visual direction

The Studio offers **Dark Modern**, **Light Modern**, **VS Code Dark+**, **Solarized Dark**, **Nord**, **Monokai**, **GitHub Dark**, **GitHub Light**, **Dracula**, **Neon Glow**, **Retro Drive**, and **High Contrast** in the global **Theme** selector. Dark Modern is the default: a graphite shell (`#181818`, `#202020`) with quiet neutral text (`#cccccc`) and a focused sky-blue accent (`#4fc1ff`). Light Modern uses a clean near-white shell with ink text and blue controls. GitHub themes use neutral grays with familiar blue controls; Dracula keeps its recognizable purple-gray surfaces and pastel accents. Neon Glow uses deep blue-black surfaces and crisp cyan graph structure, with cyan and magenta ambient light, softly illuminated graph wires, and brighter glow on active navigation, selected nodes, primary actions, and focus. Retro Drive takes its cue from late-1980s automotive instrument clusters: smoked-black surfaces, warm ivory copy, amber focus indicators, red-orange primary controls, and cyan/green display traces. The glow is static and theme-scoped; status colors and text contrast remain clear. High Contrast uses black surfaces, white text, cyan structure, and yellow focus/warning cues. The selector applies before the page styles render and remembers the choice in the current browser. The Studio reapplies it after enhanced route navigation and initializes each page's selector from the saved browser preference. Theme palettes are verified against rendered text and control surfaces for WCAG AA contrast. Navigation uses a solid theme surface and a quiet separator. High-contrast and forced-colors modes remove the decorative wash. The graph editor keeps its own readable grid and node hierarchy.

In Dark Modern, the graph canvas uses the same graphite surface as the shell (`#181818`), with node faces using the shell's raised surface (`#202020`) and a fine, low-contrast grid. Each theme carries its colors through to the graph so the canvas feels integrated with the surrounding Studio. The grid spans the viewport and tracks pan and zoom. Initial attachment and **Fit graph** frame and center the current nodes without changing saved coordinates. Semantic colors remain limited to ports, output boundaries, warnings, and recorded run states; every status also has a text label.

Typography uses the local system sans-serif stack, with a 15px shell base size and compact line spacing. Settings pages use a responsive heading scale and an 82rem content width; section headings and controls share one inset, and forms keep their field rhythm without nested card padding. Headings and controls use sentence case, left alignment, and a consistent scale. Page headings stand alone without a redundant “WORKFLOW STUDIO” eyebrow. The standalone navigation stays sticky on one theme-colored surface, while Projects, Connections, Models, and the theme selector wrap into a compact second row on narrow screens. The project picker and host destinations remain visible and keyboard accessible instead of disappearing at the mobile breakpoint. The default shell stays matte; only Neon Glow retains its theme-specific ambient tint. Focus outlines, minimum control sizes, reduced-motion behavior, and forced-colors overrides remain supported. The active activity-bar or titlebar destination exposes `aria-current="page"`; Models uses its own view heading and leaves Explorer inactive. Page navigation shows a static accent bar and polite status during slower route changes, then clears it when enhanced navigation finishes.

## Layout and embedding

The graph is bounded by its viewport; the graph world can extend beyond that viewport for pan and zoom. The background grid belongs to the viewport so it continues across the full available width even when the logical graph world is narrower. The grid position follows the world camera. Initial fit uses transient camera offsets and does not rewrite workflow layout coordinates.

The library, graph, and properties panel use one workbench grid. On narrower component containers the panels reflow and graph scrolling stays inside the canvas. The standalone theme selector changes only Studio's root tokens. Embedded Razor components do not read or persist that preference; they inherit the consumer's `--vaw-color-*`, `--vaw-font-family`, and radius tokens. Embedders can customize the graph independently with `--vaw-graph-color-canvas`, `--vaw-graph-color-surface`, `--vaw-graph-color-control`, `--vaw-graph-color-text`, `--vaw-graph-color-muted`, `--vaw-graph-color-border`, `--vaw-graph-color-control-border`, `--vaw-graph-color-focus`, `--vaw-graph-color-accent`, `--vaw-graph-color-success`, `--vaw-graph-color-error`, `--vaw-graph-color-warning`, and `--vaw-graph-color-grid`. These tokens are scoped to the graph viewport; host styles outside the component remain unaffected.

## Components and states

The graph is the visual focus. Node headers are drag handles, sockets sit on node edges, and wires represent definition connections. Labels, comments, and named sections are supporting organization tools. Selection and focus use a clear outline rather than decorative elevation.

Buttons expose default, hover, focus, pressed, and disabled states. Save and error feedback remains visible text. Node types describe workflow definition; only recorded run events drive completed, failed, or delivered states. Playback controls do not imply execution or issue model calls.

The local Playwright checks cover graph centering, full-width grid, keyboard focus, reduced motion, forced colors, contrast samples, narrow embeds, fullscreen, and graph authoring interactions. Screenshots are used for visual critique; they are not a complete accessibility audit.

## Workflow document layout

The approved workflow-document layout gives the graph the available pane between document tabs/actions and one lower panel for Runs, Output, and Problems. Workflow naming and parameters live in settings. A selected node has a compact inspector with Configure, Inputs, and Outputs views; pin views describe actual port contracts. Save and Run stay outside the graph-navigation toolbar. The IDE run inspector keeps its graph and selected execution details in a bounded side-by-side work area on desktop, with the details pane independently scrollable and an intentional stacked layout on narrow screens; run metadata stays compact and recorded-event evidence scrolls in a bounded region below the graph. The graph minimap shows the current viewport as a live outlined region and supports click-drag camera navigation. Folder-backed documents use their existing Explorer and file tabs with the same canvas/inspector styling. Their project tools are accessed from the Explorer header. Once a folder is open, Open Folder uses an anchored, bounded, scrollable panel below the compact project header; opening or selecting a project closes that panel so it cannot cover the document or project tabs.

Use `scripts/ide_shell_smoke.py` and `scripts/folder_workflow_ide_smoke.py` for document navigation, independent scrolling, execution, invalid drafts, and responsive regressions. A hidden graph must retain pending camera centering until it has measurable dimensions; opening and closing settings must not consume that pending view while the canvas is hidden.

The titlebar project switcher follows the familiar quick-picker pattern: a folder/name/chevron button opens a non-modal searchable list, with real paths for folder projects and “Catalog project” for catalog entries. Search filters locally and does not navigate; clicking a result or pressing Enter commits selection through the existing shell routing. Arrow keys move the active result, Escape dismisses and returns focus, and Tab reaches the separate Open folder/Manage projects links before leaving the picker. No global editor shortcut is overridden, and no recent-project ordering or new persistence is implied. The overlay is bounded to the viewport, scrolls for long lists, and uses the existing theme and forced-color tokens. This direction received independent proponent, opponent, and adjudicator review; native-picker accessibility was the principal implementation risk and is covered by the project-picker browser suite.
